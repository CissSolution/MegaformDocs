## 3. The punch list — every remaining delta, grouped by cause

None of these is a mystery. They fall into five buckets, and four of the five are one fix each.

### A. Consent-row text width — `agency-flyer`, `xmas-sale` (3 rows)

```
keep me updated with euroyouth news…   width 380->396
send me euroyouth updates and offers   width 212->221
i agree to the terms and conditions *  width 199->207
```

The SSR row is `<label.mf-option-item><input.mf-option-control><span.mf-option-ui>`, so the gap
between the box and the copy belongs on the **item**, not on `.mf-option-ui`. agency-flyer already
sets `.mf-option-item{display:flex;gap:12px}` and still measures 16px wide — the remaining
difference is the checkbox's own box model. **Measure `.mf-option-control`'s used width and margin
with `css-cascade-dump.mjs` before changing anything**; the mock's control is a 20px span, ours is a
native input whose UA margin survives unless it is zeroed.

### B. Chip row drift of 4–5px — `xmas-newsletter`, `xmas-sale`, `newsletter-amber` (8 rows)

```
cuisine   x-offset 507->511          weekly   x-offset 65->71
history   x-offset 584->588          monthly  x-offset 152->165
```

Cumulative: each chip is a hair wider than the mock's, so the row drifts. Cause is font metrics —
the mocks load their family through `next/font` while we load the same family from Google Fonts, and
the two rasterise a fraction differently. **Confirm before chasing**: measure one chip's width at
`font-size:12px` on both sides; if the delta is ≤1px per chip it is metric, not CSS, and should be
left alone with a note rather than "fixed" by padding.

### C. Cross-column `gap-above` — `golden-pro`, `lagoon-booking`, `invoice-*` (9 rows)

```
personal information  gap-above -532->-444     booking summary  gap-above -1929->-1916
01                    gap-above 32->50         invoice date     gap-above -18->-58
```

`gap-above` is measured against the previous element **in document order**, which in a two-column
layout is often in the *other* column. These are artefacts of column height, not spacing errors —
the harness cannot tell "next in the sidebar" from "next in the form". **Two of them are real and
worth fixing**: `invoice-navy` `01 gap-above 32->50` (our tab strip sits 18px lower than the mock's
— check the masthead's `min-height:88px` against its actual painted height) and `xmas-sale`
`language immersion gap-above 36->44` (option-card row gap).

The rest should be **excluded rather than chased**: teach the collector to skip `gapPrev` when the
previous keyed element's `dx` differs by more than half the root width, i.e. it is in another
column. That is a ten-line change in `lib/mock-collect.mjs` and it would delete seven false rows
across the batch.

### D. Card/description width tied to a sibling — `lagoon-booking` (4 rows), `invoice-spinera` (1)

```
highly spacious with private dining…  width 318->335
54 m² / 96 m²                          x-offset 396->400 / 383->400
inv-2025-001                           x-offset 450->518; width 414->80
```

In the mock these columns **shrink to the text beside them**; ours reserves a fixed gutter because
the price is absolutely positioned inside the option description. To close it, the price must become
a real flex sibling of the copy column, which means moving it out of `description` — the renderer
has no slot for it, so this needs either a `meta` slot restyled as the price column or an authored
wrapper around `{{field:room_type}}`. **This is the only structural item on the list.**

For `inv-2025-001` the cause is different and simpler: the mock's number is a bare text node of the
meta `<div>` (so the div owns it, width 414), ours is a `<span>` (width 80). Wrapping the label in a
span and leaving the number as a text node would match — but then the live script has nothing to
target. Accept, or give the script the div and re-render both parts.

### E. Single-row leftovers

- `product-order` — `tax (10%) width 59->66`. Text metric. Leave.
- `invoice-navy` / `invoice-spinera` — `next step x-offset 601->605` / `next 762->766`. 4px on a
  right-aligned button; check `padding:10px 24px` against the mock's `px-6 py-2.5` and the icon gap.
- `job-application`, `invoice-navy` — `copy missing 1` each. Identify which string before assuming
  it is decorative.

## 5. Running the sweep

```powershell
# one template, ~50s: regenerate -> copy -> re-seed -> measure -> build the sheet
powershell -File tools\browser-qa\iterate-template.ps1 -Slug xmas-sale
powershell -File tools\browser-qa\iterate-template.ps1 -Slug xmas-sale -SkipBuild -SkipSeed   # 13s

# every measured template's deltas into one file
node -e "const fs=require('fs');const d=fs.readdirSync('qa-out/iter',{withFileTypes:true}).filter(x=>x.isDirectory()).map(x=>x.name).sort();const o=[];for(const s of d){const p='qa-out/iter/'+s+'/report.json';if(!fs.existsSync(p))continue;const r=JSON.parse(fs.readFileSync(p,'utf8'));o.push({slug:s,matched:r.matched,differing:r.differing,px:r.bitmap.mismatch,miss:r.structure.missingText.length,rows:r.rows.map(x=>x.key+': '+x.diffs.join('; '))})}fs.writeFileSync('qa-out/iter/deltas.json',JSON.stringify(o,null,1));console.log(o.map(x=>x.slug+' '+x.differing).join('\n'))"
```

**Suggested order for the sweep**, cheapest evidence first:

1. Build **invoice-codexo** (§2) — it is the only thing actually missing.
2. Land the **collector change in §3C** — it deletes seven false rows across four templates before
   anyone spends time on them.
3. Fix the two real `gap-above` rows named in §3C.
4. Measure §3A properly (dump the checkbox's box model) and fix once for both templates.
5. Decide §3B and §3D: both may be correctly left alone with a note. Do not "fix" a font metric with
   padding — that trades a 4px measurement for a wrong design.

### One trap this pass added, which is not in the other handoff

⚠️ **`data-mf-echo` belongs to the renderer's echo runtime.** A node whose key matches no field is
**blanked and stamped `.is-empty`** — eight lines of invoice-spinera's masthead vanished that way and
measured as missing copy. Use a private attribute (`data-spn="…"`) for anything a custom script owns.
The templates that already use `data-mf-echo` successfully (rose's meter, product-order's totals)
survive only because their script happens to run last.

### One mess this session made, left deliberately un-undone

Re-seeding was done with `Copy-Item …\DONEE\*.json` instead of the 14 named files. DONEE holds
**63** templates, so the site's catalog went 53 → 96 and `DevBulkCreateForms` created **43 extra
forms, ids 72 and up**. Forms 57–71 and all fourteen review pages are unaffected — the strays are
other premium templates that simply got seeded onto a QA site.

They were NOT rolled back: `Copy-Item` preserves `LastWriteTime`, so the files it added cannot be
told apart from the ones that were legitimately there, and deleting by name would have removed six
templates that belonged to the site. Undoing it wrongly is worse than the clutter. **Next session:
ignore forms with an id ≥ 72, or clean them deliberately with a list built from
`DevBulkCreateForms`'s own `items[]` mapping.** Use `iterate-template.ps1`, which copies exactly one
file, rather than an ad-hoc glob.
